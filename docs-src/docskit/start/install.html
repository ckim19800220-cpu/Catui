테마는 다른 확장과 같은 규칙(저장값이 없으면 시스템)이고, <html data-catui-theme-lock>이 있으면 건드리지 않습니다(이 문서 사이트가 그렇습니다).

템플릿 · 메뉴

  • templates/docskit/pages/이름.html — 머리 주석 <!-- title: 블로그 | nav: blog | layout: blank -->. nav는 머리 메뉴의 현재 위치입니다.
  • templates/docskit/menu.json — top(머리 메뉴) · foot(바닥글 링크). 없는 화면은 메뉴에서 빠집니다. 문서 왼쪽 메뉴는 JSON 모의 데이터 data/nav.json에서 그립니다.
  • npm run build → docs/docskit/templates/. 검사: 정의 안 된 클래스·없는 아이콘·id 중복·label·화면 링크(버전 선택 주소 포함)·h1·안 쓰인 클래스·역할 없는 span의 aria-label·JSON 문법, CSS의 hex·없는 토큰·본체 클래스 재정의.

JSON 모의 데이터

templates/docskit/data/*.json → docs/docskit/templates/data/. 실서비스는 같은 모양의 정적 JSON이나 API를 만들고 catui.docs.dataBase = '/api/docs/'만 바꿉니다. 읽는 시간·태그별 글 수·관련 글은 저장하지 않고 원자료에서 계산합니다.

데이터 파일
파일내용 · 계산
nav.json문서 메뉴 묶음 [{ title, items: [{ title, href }] }] — 순서가 이전/다음, 지금 쪽은 파일 이름 + ?p=로 판단
pages.json문서 본문 조각 { id: { title, group, desc, updated, edit, blocks } } — doc.html?p=id
posts.json블로그 글 {{stat:dkPosts}}개 — 저자·날짜·태그·머리 그림 색·본문 블록. 최신 순·읽는 시간·관련 글(태그 겹침 수)은 계산
authors.json · tags.json저자(역할·소개·사이트) · 태그(이름·설명) — 태그별 글 수는 계산
changelog.json버전·날짜·항목(added·changed·fixed) → 배지 “추가·변경·고침”
search-index.json검색 색인 { t, u, s, x, k } — 화면 안 인라인 색인이 있으면 그쪽을 먼저 씀

본문 블록: { h2 } · { h3 } · { p } · { list: [] } · { code, lang } · { note, tone: "tip"|"warn" }. 글자는 모두 이스케이프하고 p·list·note만 마크다운 일부(굵게·코드·https 링크)를 바꿉니다.

기억하는 상태

catui.data('docs')(localStorage "catui:docs") 한 곳에 theme와 helped(쪽마다 피드백 “예/아니오”)를 둡니다. 블로그 태그·쪽 번호는 기억하지 않고 주소(?tag=&page=)에 남겨 공유·뒤로 가기가 그대로 됩니다.
