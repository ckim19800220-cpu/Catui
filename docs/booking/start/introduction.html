    CatuiBooking은

    Catui(CSS 키트 + catui.js) 위에 얹는 예약·일정 확장입니다. CatuiShop·CatuiDocs와 같은 구조로, 본체 컴포넌트(단계 표시·버튼·폼 검증·레이어·표)를 그대로 쓰고 예약 화면에 필요한 것 — 시간 칸, 남은 자리, 좌석 배치도, 숙박 요금, 환불 규정, 관리자 일정표 — 만 더합니다.

    화면 지도

    각 화면은 새 창에서 전체 화면으로 열립니다. 예약 단계는 서비스 종류마다 다릅니다 — 시간 예약(클래스·미용): 날짜·시간 → 인원·옵션 → 정보 → 확인, 좌석 예약(공연·식당): 날짜·회차 → 인원 → 좌석 → 정보 → 확인, 숙박: 기간·객실 → 정보 → 확인.

    행사·업종별 템플릿 팩

    팩 선택 화면에서 행사·식당·숙박·클래스로 시작합니다. 별도 CatuiEvents 엔진 없이 기존 날짜·회차·인원·좌석·객실·예약 확인을 재사용합니다.

    • 행사: 소개 · 프로그램 · 가상 연사 · 참가 안내. 2026년 11월 14일 14:00 한 회차, 150분, 지정 좌석 12석의 가상 워크숍입니다.
    • 업종별: 식당은 예약금·테이블 정원, 숙박은 기간·객실·박별 요금, 클래스는 정원·지점·인원별 옵션을 중심으로 안내합니다.
    • 원자료: templates/booking/data/packs.json에 소개·프로그램·연사·안내·서비스 연결을 작성합니다. 금액과 장소는 기존 서비스·좌석·객실·지점 자료에서 빌드하며 참가 신청 링크도 같은 자료로 생성합니다.
    • 행사 서비스의 선택적 dates 배열은 허용 날짜입니다. 배열이 있으면 다른 날짜의 시간 칸과 직접 확정을 모두 막습니다. 필드를 생략한 기존 서비스는 기존 날짜 규칙을 유지합니다.
    • 서비스의 branches 배열에 포함된 지점만 시간 조회·단계 진행·최종 확인을 허용합니다. 존재하는 지점이어도 해당 서비스의 제공 지점이 아니면 재선택을 안내하고 예상 금액을 숨깁니다. 확정 직전 바뀐 초안도 다시 검사합니다. 실서비스 서버에서도 같은 관계를 검증해야 합니다.
    • 소개는 정적 HTML로 빌드되어 예약 JSON 요청 실패와 무관하게 읽을 수 있습니다. 신청 단계는 기존 실패 안내·재시도·선택 보존을 사용합니다. 실제 결제·문자·QR 입장 처리는 포함하지 않습니다.

    로그인·비밀번호 표시·권한 없음 안내는 templates/shared/ 공통 조각을 사용합니다. 실제 인증·인가와 개인정보 접근 검사는 서버에서 구현해야 합니다.

    접근성 · 반응형 기준

    • 시간 칸·날짜·좌석·일정 블록의 상태는 글자(“3자리 남음”·“마감”·“지난 시간”·“예약됨”·“장애인석”·“겹침”)와 아이콘·빗금·점선을 함께 씁니다 — 색만으로 알리지 않습니다.
    • 좌석 배치도는 키보드로 움직이는 격자이므로 ARIA grid 패턴(role="grid" > row > rowheader·gridcell)을 제대로 씁니다: Tab 한 번에 들어가 화살표로 이동(roving tabindex), 통로는 건너뜀, Space·Enter로 선택(aria-pressed), 예약된 좌석은 aria-disabled로 초점은 받되 고를 수 없음.
    • 달력은 날짜를 고르는 단추 묶음이라 role="grid" 대신 표(요일 머리·caption) + 단추, 관리자 일정표는 보기 전용이라 열마다 제목 + 시간 순 목록입니다. 빌드가 키보드 격자가 아닌 곳의 role="grid"를 막습니다.
    • 숨김 글자는 .Catui_clip — 역할 없는 span에 aria-label을 쓰지 않습니다(빌드가 검사). 한글 조합 중 키 입력은 catui.imeBusy로 거릅니다.
    • 320px 화면에서 쪽 가로 넘침 없음. 좌석 배치도·일정표·표는 position:relative 스크롤 상자 안에서만 가로로 밀립니다. 모션은 누름·체크 나타남뿐이고 prefers-reduced-motion이면 끕니다.
